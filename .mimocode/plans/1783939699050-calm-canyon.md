# Fix: Login 401 Unauthorized + DOM Autocomplete Warning

## Context
The deployed app at imobweb2.vercel.app returns 401 on POST `/api/auth/login`. User confirmed env vars are set and test users exist. The 401 comes from Supabase's `signInWithPassword()` — we need visibility into the actual error and better error handling.

## Changes

### 1. Add error logging + better error response to login route
**File:** `app/api/auth/login/route.ts`
- Add `console.error` with the Supabase error message, status, and code before returning 401
- Return the actual Supabase error message to the client (already done, but add logging for Vercel function logs)
- Add input validation (empty email/password check)

### 2. Add autocomplete attributes to login form
**File:** `app/login/page.tsx`
- Email input: add `autoComplete="email"`
- Password input: add `autoComplete="current-password"`

### 3. Add autocomplete to register form
**File:** `app/register/page.tsx`
- Name: `autoComplete="name"`
- Email: `autoComplete="email"`
- Phone: `autoComplete="tel"`
- Password: `autoComplete="new-password"`
- Confirm password: `autoComplete="new-password"`

### 4. Add autocomplete to forgot-password form
**File:** `app/forgot-password/page.tsx`
- Email: `autoComplete="email"`
- New password: `autoComplete="new-password"`

### 5. Show Supabase error details to user on login failure
**File:** `app/login/page.tsx`
- Update the `setError("email", ...)` call to include the actual Supabase error message so the user sees what went wrong (e.g., "Invalid login credentials", "Email not confirmed", etc.)

## Verification
1. Deploy and check Vercel function logs — the `console.error` will show the actual Supabase error
2. Try login again — the error toast should now show the specific Supabase reason
3. Confirm DOM autocomplete warnings are gone in browser console
